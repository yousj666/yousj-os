# Yousj OS · 服务器版 userland 设计（init + Shell）

> 地盘：`userland/`（旁聊 B）。状态：设计稿，待总协调验收。
> 接口唯一依据：`kernel/include/yousj/syscall.h`（下称 syscall.h）。
> 本文不新增任何 syscall 号；觉得缺的号只在第 7 节列**提案**，等协调者批。
> 现状前提（2026-11-01）：阶段 1 的 PMM 已完成；调度器、进程模型、
> `execve`、VFS/文件系统、控制台输入都**还没有落地**。所以本文是
> 「目标设计 + 落地依赖标注」，配套的 `minishell.c` 是在 Linux 宿主机上
> 用 POSIX 接口验证交互逻辑的原型，不是在 Yousj 上能跑的成品。

## 1. 定位与范围

服务器版第一里程碑（见 `docs/DIVISION.md`）：

```
内核启动 → 控制台可用 → init（PID 1）起来 → Shell 能敲命令
```

- 服务器版无图形：init 和 Shell 只面对串口/控制台和文件，不涉及
  帧缓冲、窗口、桌面。桌面版以后复用同一套 init/Shell 思路，只是
  多一个图形会话的拉起方式，不在本设计内。
- userland 第一批只做两个程序：
  - **init**：PID 1，系统第一个用户态进程，负责把系统从「内核刚就绪」
    带到「有人能登录操作」，并在运行期兜底回收进程、处理关机。
  - **shell（yousj-sh）**：交互式命令行解释器，人敲命令的主要入口，
    也是 init 拉起的第一个（服务器版：唯一必需的）前台程序。
- 基础工具（ls/cat 等独立小工具）不在第一批：先由 shell 内建顶住
  最小可用集，独立工具等 VFS 和 execve 稳定后再拆出去。

## 2. init 设计

### 2.1 职责总览

| 职责 | 说明 | 依赖 |
|---|---|---|
| 建立标准通道 | 确保 fd 0/1/2 指向控制台（串口控制台） | 控制台驱动、`open`(2)/`dup`(32) |
| 挂载文件系统 | 挂根文件系统；伪文件系统（如 proc 类）留待 VFS 成型后 | VFS；`mount` 尚无号，见提案 P1 |
| 拉起 shell | `clone` 出子进程，子进程 `execve` 成 shell，自己不替换 | 调度器、`clone`(56)、`execve`(59) |
| 回收僵尸 | 循环 `wait4` 收走所有已退出子进程，包括被过继来的孤儿 | `wait4`(61)、信号机制（见提案 P4） |
| shell 守活 | 前台 shell 退出/被杀后，按策略重新拉起（服务器版默认重拉） | `wait4`(61) 的返回值区分 |
| 关机语义 | 收到关机请求时：停拉新 shell → 通知/等待子进程退出 → 同步文件系统 → 请求内核关机/重启 | `kill`(62)；`sync`/`reboot` 尚无号，见提案 P2/P3 |
| 兜底日志 | 把拉起、退出码、重拉、关机等关键事件用 `write` 写到控制台 | `write`(1) |

### 2.2 启动顺序（目标流程）

1. 内核完成内存/调度初始化后，按约定创建第一个用户态进程并跳到
   init 入口，PID 必须为 1（`getpid`(39) 自检，不为 1 只打日志不自杀，
   避免早期 bring-up 时无意义地把系统带崩）。
2. init 检查 fd 0/1/2：若未打开，则 `open` 控制台设备补齐，再用
   `dup` 复制到 0/1/2。服务器版控制台即串口，与 kmain 现阶段
   「只走串口」的口径一致。
3. 挂载：根文件系统应由内核在跳 init 前挂好，或由 init 用未来的
   `mount` 完成——**此点等 VFS 设计定版，本文不预设**。伪文件系统
   挂载在第一里程碑不做要求。
4. init 打印一行启动信息（含 `uname`(63) 的系统名/版本，若内核已实现），
   然后进入「拉起 shell + 回收」主循环。

### 2.3 主循环与僵尸回收

- PID 1 是所有孤儿进程的过继父进程。任何没人收尸的退出进程都会
  变僵尸挂在 init 名下，所以 init **必须**持续回收，这是硬职责，
  不是可选优化。
- 主循环形态：阻塞在 `wait4`(-1, &status, 0) 上：
  - 收到的若是前台 shell → 记录退出码/被杀信号，按守活策略重拉
    （带最小重拉间隔，避免 shell 一启动就崩时疯狂刷屏；间隔可用
    `nanosleep`(35) 实现）。
  - 收到的若是其他子进程（未来的服务、孤儿）→ 只记录并回收。
  - 理想形态还要配合 SIGCHLD 信号避免竞态，但信号相关 syscall
    尚无号（提案 P4）；在信号落地前，先用纯 `wait4` 阻塞回收，
    语义正确、只是不够精细，第一里程碑够用。
- init **绝不能退出**：PID 1 退出在 Linux 语义下等于内核 panic。
  Yousj 内核侧对「PID 1 退出」的处理（panic/关机）由内核定，
  userland 侧的约定是：init 主循环所有错误路径都只记日志并继续
  循环，连 `execve` 拉 shell 失败也只是隔一会儿重试。

### 2.4 关机语义

- 触发来源（第一里程碑只做第一种）：
  1. shell 内建命令 `poweroff`/`reboot` 向 init 发请求（实现形态：
     给 init 发信号或写约定的请求——信号落地前先占位，见提案 P4）；
  2. （以后）远程管理/ACPI 电源事件，不在本阶段。
- 关机流程：停止重拉 shell → 给现存子进程发 `kill`(62) 先 TERM
  后（等待超时再）KILL → `wait4` 收干净 → 同步文件系统（提案 P3）
  → 调内核关机/重启入口（提案 P2）→ 若该调用返回，init 进入
  `nanosleep` 死循环等待内核处理，绝不 `exit`。
- `exit`(60) 对 init 永远禁用，这条写进 init 的代码规范。

## 3. Shell（yousj-sh）设计

### 3.1 基本形态

- REPL：打印提示符 → `read`(0) 读一行 → 分词 → 派发 → 回到提示符。
- 提示符：`用户@主机:当前目录 $ ` 的简化版，第一版做
  `yousj:<cwd> $ `，其中 cwd 来自 `getcwd`(79)，取不到时显示 `?`。
  是否交互（管道输入时不打提示符）用 `ioctl`(16) 对 fd 0 探测
  终端属性来判断；探测方式等控制台驱动定版后对齐。
- 分词：第一版只做空白分词（空格/Tab），**不支持**引号、转义、
  通配符展开、变量展开、注释。这些是后续增量，不进第一里程碑，
  以免在还没有进程/文件系统时把 shell 本身做成大工程。
- 行编辑/历史：第一版没有（靠终端行规程回显退格）；等控制台驱动
  的行规程明确后再评估是否在 shell 里做简易历史。

### 3.2 内建命令 vs 外部命令

内建必须在 shell 进程内执行，因为它们要改 shell 自身状态
（cwd、退出）或本质上没有外部程序可调：

| 内建 | 语义 | 用到的已定 syscall |
|---|---|---|
| `cd [目录]` | 改 shell 的工作目录；无参回初始目录（第一版定为 `/`） | `chdir`(80) |
| `pwd` | 打印当前工作目录 | `getcwd`(79)、`write`(1) |
| `echo [参数...]` | 参数以空格连接打印并换行 | `write`(1) |
| `exit [码]` | 退出 shell（init 会按守活策略决定是否重拉） | `exit`(60) |
| `help` | 打印内建与可用命令列表 | `write`(1) |
| `uname` | 打印系统信息（验证 `uname` 打通的探针命令） | `uname`(63)、`write`(1) |
| `sleep 秒` | 睡眠（验证定时器/调度让出） | `nanosleep`(35) |
| `poweroff` / `reboot` | 向 init 发关机/重启请求（形态见 2.4，未落地前只打印提示） | `kill`(62)（给 PID 1 发信号，需提案 P4 先落地信号） |

外部命令（独立程序文件，shell 只负责拉起）：

| 外部（规划） | 语义 | 用到的已定 syscall（shell 侧 + 程序侧） |
|---|---|---|
| 任意 `/bin/*` 程序 | shell 查找路径后执行 | shell：`clone`(56)、`execve`(59)、`wait4`(61)；程序侧自理 |
| `ls [目录]` | 列目录 | `open`(2)、`getdents64`(217)、`close`(3)、`write`(1) |
| `cat 文件` | 打印文件内容 | `open`(2)、`read`(0)、`write`(1)、`close`(3) |
| `mkdir 目录` | 建目录 | `mkdir`(83) |
| `kill PID` | 给进程发信号 | `kill`(62) |

说明：
- `ls`/`cat`/`mkdir` 第一里程碑可先做成内建**过渡形态**顶住可用性，
  等 execve 稳定后拆成外部程序；拆分时命令名与用法不变。
- 管道与重定向：`pipe`(22) 已有号，但把管道端接到子进程的
  0/1 号 fd 需要 `dup2` 类语义，现有 `dup`(32) 只能分配最低空闲 fd、
  不足以精确接线 → 管道/重定向**明确推迟**，缺的号见提案 P5。

### 3.3 外部命令执行流程（目标形态）

1. 在约定路径（第一版只查 `/bin`，PATH 环境变量等 execve 的
   envp 语义定版后再做）拼出候选路径。
2. `clone`(56) 出子进程——**注意**：syscall.h 里没有独立的 fork 号，
   Linux x86-64 本来就是用 `clone` 实现 fork；Yousj 的 fork 语义
   具体走 `clone` 的哪组标志组合，等调度器/进程设计定版（见第 6 节）。
3. 子进程 `execve`(59) 换像；失败则向 fd 2 打印错误并 `exit`(60)
   （退出码约定 127 表示「命令不存在/无法执行」，与常见 shell 一致）。
4. 父进程（shell）`wait4`(61) 等待，取退出码；被信号杀死的情况
   要能区分打印（如 `killed by signal N`），依赖 wait 状态字定义
   与 Linux 兼容——此点请内核侧在调度器设计里明确。

### 3.4 错误处理约定

- 所有 syscall 返回负错误码（Linux 约定 -errno）——userland 按此
  假设写错误打印；若内核最终不用此约定，shell/init 的错误路径
  要整体改，请协调者在进程/VFS 设计里尽早拍板。
- 提示风格：`yousj-sh: <命令>: <错误简述>`，只打到 fd 2，不混 stdout。

## 5. 与 Linux 程序兼容目标的关系

- **号对齐红利**：syscall.h 的号与 Linux x86-64 一致，意味着将来
  （阶段 2）无修改的 Linux ELF 程序在 Yousj 上跑时，它调的
  read/write/execve/wait4 等正是 init/shell 先用熟的同一批号。
  userland 先行把这批号的语义（错误码、wait 状态字、getdents64
  的目录项格式）踩实，等于给 Linux 兼容层探路：兼容测试可以先拿
  自家 shell 当被测对象，再换真 Linux 程序。
- **shell 本身可作兼容样本**：yousj-sh 若用普通 C 写、只依赖上表
  的号，它的 ELF 理论上应能同时在 Linux 与 Yousj 上运行；
  `tools/run-check.sh` 与宿主机原型（`minishell.c`）就是按
  「先在 Linux 上验证逻辑、再搬到 Yousj」的节奏设计的。
- **Wine 层在更上面**：EXE 经 Wine 式用户态层翻译成同一批 syscall，
  init/shell 不感知 EXE 的存在——shell 里敲一个 EXE 名，本质仍是
  execve 一个（经兼容层处理的）映像，细节归阶段 4，本文不展开。
- **不承诺的**：环境变量全套语义、PATH 搜索、动态链接器行为、
  信号全套、作业控制（fg/bg、Ctrl-C 进程组）都不在第一里程碑；
  它们是阶段 2 Linux 兼容核心的内容，shell 随之增量补齐。

## 6. 明确标注：要等落地的部分

| 事项 | 等谁 | 影响本文哪部分 |
|---|---|---|
| 调度器 + 进程模型（task 结构、PID 分配） | 内核（协调者） | init 成为 PID 1、shell 被拉起，前提 |
| `clone` 的 fork 语义标志组合 | 内核进程设计 | 3.3 的执行流程第 2 步 |
| `execve` + ELF 加载器 | 内核（阶段 2 核心） | 一切外部命令、init 拉 shell |
| wait 状态字定义（退出码/信号编码） | 内核进程设计 | 3.3 第 4 步、init 守活判断 |
| VFS + 根文件系统格式 + 控制台设备路径 | 内核 VFS 设计 | init 挂载与开控制台、`ls`/`cat` |
| 控制台输入驱动（串口读、行规程、回显） | 驱动侧 | shell 的 `read` 读行 |
| 信号投递机制 | 内核（需先批提案 P4） | SIGCHLD 回收、`poweroff` 请求、Ctrl-C |
| 关机/重启内核入口 | 内核（需先批提案 P2） | 2.4 关机流程最后一步 |

在以上落地前，userland 能推进的只有：本文设计、宿主机原型
（`minishell.c`，POSIX 接口验证 REPL/分词/内建/外部命令逻辑）、
以及检查脚本（`tools/run-check.sh`）。不假装能在 Yousj 上运行。

## 7. 给协调者的 syscall 提案（只提案，不自行加号）

以下号在 syscall.h 中**尚不存在**，括号里是 Linux x86-64 的同名号，
仅供协调者参考是否沿用 Linux 号保持兼容；批或不批、用什么号，
由协调者定，userland 在批复前不用。

- **P1 mount(165) / umount2(166)**：init 挂载根/伪文件系统所需。
  若根文件系统改由内核挂好，则 P1 可降级为「以后再说」。
- **P2 reboot(169)**：关机/重启的内核入口，init 关机流程的最后一步；
  或者给一个 Yousj 原生号（0x1000 段）做 poweroff/reboot，也请协调者选。
- **P3 sync(162)**：关机前刷盘；若 VFS 保证 `reboot` 内部同步，可不批。
- **P4 rt_sigaction(13) / rt_sigprocmask(14) / rt_sigreturn(15)**：
  信号三件套。SIGCHLD 精细回收、shell 的 Ctrl-C 处理、`poweroff`
  请求信号都依赖它。工作量不小，可排在 wait4 纯阻塞回收跑通之后。
- **P5 dup2(33)（或 dup3(292)）**：管道/重定向接线必需，只有 `dup`(32)
  无法把 fd 精确放到 0/1。批了它，`pipe`(22) 才能真正用起来。
- **P6 newfstatat(262) 及/或 stat 家族**：`ls -l`、判断路径是否存在/
  是文件还是目录都需要元数据查询；现表里完全没有 stat 类号，
  ls 只能列名字。建议至少批一个。
- **P7 unlink(87) / rmdir(84) / rename(82)**：`rm`/`mv` 类基本工具，
  不急，可随 VFS 一起排期，先登记防号段被占。

## 8. 配套原型说明

- `userland/minishell.c`：宿主机原型，实现提示符、读行、空白分词、
  内建 `cd`/`pwd`/`echo`/`exit`/`help`、外部命令
  fork+exec+wait、空行跳过、Ctrl-D（EOF）退出。文件头注释里有
  POSIX → Yousj syscall 的逐项对应表，移植时按表替换即可。
- 原型与目标 shell 的已知差异（诚实清单）：宿主机用 `fork`，
  Yousj 用 `clone`(56) 的 fork 语义组合；宿主机用 `execvp` 自带
  PATH 搜索，Yousj 第一版由 shell 自己拼 `/bin` 路径后 `execve`；
  宿主机 `waitpid` 对应 `wait4`(61)。这些差异不改变 REPL 与内建
  的逻辑结构，正是原型要验证的部分。
